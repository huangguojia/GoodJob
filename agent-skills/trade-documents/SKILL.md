# 贸易单据制作与交付

## 执行流程

1. 从用户原话解析客户、商机、单据类型以及是否包含导出或下载。
2. 优先使用页面选择的对象；否则查询真实客户，再从该客户的可见商机中按标题、产品和阶段匹配唯一商机。
3. 读取贸易单据接口契约，不猜测字段、路径或状态流转。
4. 仅使用真实客户、商机、商品、数量、价格和币种制作单据。缺失贸易条款使用“待确认”，不得伪造地址、银行或付款事实。
5. 创建后保存 `document.id`。目标包含下载时，继续提交审批；当前角色有审批权限时完成审批，再调用导出接口。
6. 导出后取得 `document.id`、`job.id` 和 `fileName`，在界面提供打开单据与下载动作。

## 完成标准

- 创建：`POST /api/trade-documents` 返回目标客户与商机关联的 `document.id`。
- 审批：导出前单据真实状态为 `approved` 或 `exported`。
- 下载：`POST /api/trade-documents/{id}/export` 返回 `document.id`、`job.id` 和 `fileName`。
- 复合目标必须全部满足；读取客户、商机概览或接口目录不能替代任何完成证据。

## 失败恢复

- 客户重名或多个商机无法区分：只询问一个最关键的消歧问题。
- 当前角色无审批权限：保留已创建单据，明确说明待主管审批，不虚报已下载。
- 接口契约或状态不匹配：读取当前单据状态后重新规划，不重复创建同一份单据。
- 模型计划无法解析：保留原始错误并切换服务端确定性目标契约，不降级为无关概览查询。
