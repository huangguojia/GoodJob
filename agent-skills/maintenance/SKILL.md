# 客户自动维护

## 适用目标

发现掉队的客户（长期未跟进、健康度下滑、商机停滞），按顶尖销售的打法生成下一步动作建议，并落地为站内待办；用户要求批量唤醒客户时，引导其使用自动维护中心与发信批次，而不是逐个手工跟进。

## 执行流程

1. 先用 `maintenance.preview` 预检命中：向用户说明会命中多少客户、每条为什么命中（reasonCodes），不要未经预检直接创建守护策略。
2. 与用户确认守护策略参数：客户等级范围（建议先收窄到 A / B 试跑）、未跟进阈值天数、健康度阈值、巡检周期、单次建待办上限。
3. 参数确认后用 `maintenance.create_watch` 创建守护策略；界面入口在「自动维护中心」的策略矩阵。
4. 巡检由后台按周期执行：命中 → 匹配销售打法（按客户等级联动）→ 生成带「自动维护」来源徽章的站内待办。
5. 用户在待办中心按「自动维护」筛选处理；每条待办都要能回答「为什么是它」与「下一步做什么」。
6. 需要发信唤醒时，走「发信批次」：勾选候选 → 生成批次 → 预览勾选 → 一次冻结放行。机器绝不直接对外发信。

## 安全补全

- 可使用：站内待办、原因码说明、来自打法的建议动作文本。
- 不可生成：虚假跟进记录、虚构客户回复、未经冻结确认的对外邮件或消息、自动覆盖客户资料字段。

## 完成标准

- 守护策略已创建且状态为 active，能在自动维护中心看到下一次巡检时间。
- 预检命中数与实际建待办数一致（或在单次上限内）。
- 每条自动维护待办都带原因码与建议动作，且能在待办中心被单独筛选。
- 最终回复说明命中了多少客户、建了多少待办、下一步在哪里处理。

## 失败恢复

- 预检命中 0：检查客户等级范围与阈值是否过严，建议放宽后再试。
- 巡检报错：读取 `maintenance.get_progress` 的 lastError，修正策略参数后重建。
- 待办被误建：在待办中心标记「无需处理」，并在守护策略中收窄等级范围。
- 发信需求：引导走发信批次冻结确认；若用户坚持逐封群发，说明红线后拒绝。
