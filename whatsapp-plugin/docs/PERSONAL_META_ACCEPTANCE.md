# 个人版与 Meta 免费测试验收

本手册把“本地产品验收”和“真实 Meta Cloud API 验收”严格分开。第一阶段通过，只代表 CRM 功能和操作闭环可用，不代表 Meta 凭据、公网 Webhook 或生产交付已经通过。

## 1. 当前个人版验收

打开 `http://127.0.0.1:5188/`，登录 GoodJob CRM，然后进入 `Communication`。

1. 打开“会话”，选择 `Maria Garcia`，展开客户详情。
2. 确认客户摘要、购买意向、风险、特点、证据消息、跟进项、CRM 概览和最近会议都能显示。
3. 打开任一客户特点，确认结论可以追溯到原始消息。确认或忽略一次特点，刷新客户后检查结果是否保留。
4. 把一条跟进项转为 GoodJob 待办。返回 CRM 工作台，核对标题、优先级、截止时间、客户和 WhatsApp 证据。
5. 在 CRM 完成该待办，再回到 Communication，确认对应跟进项不再处于待处理状态。然后反向从 Communication 完成一条跟进，检查 CRM 待办是否同步完成。
6. 打开“自动化节奏”，点击“立即运行一轮”，检查运行结果、执行进度、交付明细、重试次数和 CRM 外部对象编号。
7. 打开 CRM“消息通知”，确认每日通知包含客户、号码、原因和查看消息入口。
8. 打开“商业上线”。真实 Meta、公网 HTTPS、Webhook、AI 或目标数据库条件缺失时，页面必须继续阻止上线，不能显示假通过。

本阶段只使用测试客户。不要把真实客户导出、生产 Token 或员工日常使用的 WhatsApp 号码放入本地验收账号。同一时间只使用一个 Communication 数据环境，切换数据库后不要重复运行旧环境的定时任务。

## 2. 需要用户本人准备的内容

以下步骤会创建法律主体关系、接受 Meta 条款或授予业务权限，必须由企业所有者或被正式授权的管理员本人操作：

1. 使用企业可长期控制的账号登录 Meta for Developers。
2. 创建 Meta App，添加 WhatsApp 产品，第一轮先使用 Meta 免费测试资产。
3. 在 Meta 后台保存 App ID、App Secret、Verify Token、WABA ID、Phone Number ID 和临时 Access Token。不要通过聊天或截图发送这些值。
4. 准备一个能接收 Meta 测试消息的手机号码，不要使用正式销售主号码。
5. 明确谁可以查看客户聊天、数据保留多久，以及客户提出删除或导出请求时由谁处理。

系统维护者可以配置 HTTPS 和执行技术测试，但只有账号所有者适合创建 App、接受条款、授予企业权限以及批准正式号码迁移。

## 3. 配置 Meta 免费测试

1. 在 Communication 打开“商业上线”，按每项“去处理”进入对应配置页。
2. 在“接入设置”保存 Meta App ID、App Secret 和新生成的 Verify Token。
3. 在“账号与扫码”创建 Meta 账号，绑定 WABA ID、Phone Number ID 和临时 Access Token。
4. 将产品显示的公网 HTTPS 回调地址配置到 Meta Webhooks，并订阅 WhatsApp Business Account 的消息事件。
5. 重新执行连接检查。只有号码配置存在且真实 Graph 校验成功，“Graph API 连接”才允许通过。

Meta Token 禁止写入源码、Git 提交、浏览器截图、测试报告或普通 CRM 备注。

## 4. 真实 Meta 端到端验收

按顺序执行，并在验收记录中保存时间和消息 ID：

1. 从获准的测试手机向 Meta 测试号码发消息。Webhook 到达服务器后，消息应在 3 秒内出现在 CRM。
2. 重放同一个 Webhook，CRM 会话中必须仍然只有一条消息。
3. 分别发送价格、数量、样品、交期、付款和会议内容。运行分析，检查每个特点和跟进项都有原始消息证据。
4. 连续执行两次每日自动化，第二次不得重复创建待办或站内信。
5. 在 CRM 完成待办，检查 Communication 跟进同步完成；恢复待办后，跟进应重新待处理。
6. 在 24 小时服务窗口内回复自由文本，检查发送、送达和已读状态只能向前推进。
7. 在 24 小时窗口外测试，自由文本必须被阻止，并要求使用已审核模板。
8. 暂停 CRM 后执行自动化，确认出现失败交付记录；恢复 CRM 后重试，必须成功且不能重复创建。
9. 重启 Communication，确认 Meta 配置、消息、客户分析、跟进项和交付历史仍然存在。

“商业上线”仍有假阳性、失败没有审计记录或重复数据未解释时，不得签署 Meta 测试通过。

## 5. 个人版通过后的边界

通过本手册后，可以进入单企业、单实例、受控人员范围的试运行，不能直接作为公开多客户 SaaS 上线。

公开 SaaS 前仍需完成组织级 RBAC、全表租户身份、持久任务队列和出站 Outbox、多实例租约、Socket.IO 多实例适配、隐私导出与删除、自动备份恢复演练、密钥轮换、监控告警和事故手册。
