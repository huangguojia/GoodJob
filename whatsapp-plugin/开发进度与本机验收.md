# WhatsApp CRM 插件开发进度与本机验收

日期：2026-07-17

## 当前里程碑

Baileys 与 Meta 双通道工作台已实现并可在本机运行。当前版本用于在真实 CRM 接入前验证多账号、登录、联系人、消息、翻译、路由、接入切换和 CRM Sandbox。

## 已实现

- 多 WhatsApp 账号池，账号级联系人、会话、消息、幂等键和实时事件隔离。
- Baileys `7.0.0-rc13` 非官方通道，真实二维码登录、二维码轮换、连接状态和指数退避重连。
- Baileys 可选 HTTP(S) CONNECT 代理，只作用于 WhatsApp WSS、媒体和版本请求，不改变 Meta、AI 或 CRM 流量。
- Meta Cloud API 官方通道：Graph 号码/WABA 归属校验、Webhook 订阅验证与 HMAC 签名校验、入站文本、单调状态回执、24 小时窗口和审核模板发送。
- 免费优先、官方优先、混合共存三种策略；固定策略不允许矛盾的默认 Provider，策略变更不会迁移或删除已有账号。
- 同一手机号默认禁止在 Baileys 与 Meta 活跃通道重复运行；切换保留旧数据，但不迁移 Provider 身份和消息 ID。
- Baileys AuthState、AI API Key、Meta App Secret 与 Meta Access Token 使用 AES-256-GCM 加密落库；Meta Verify Token 只保存摘要与掩码。
- Demo Provider 仅在显式开启开发能力并执行 `db:seed-demo` 后可用；正常启动默认零演示数据。
- 联系人/历史事件入库、会话列表、实时入站消息和幂等文本发送。
- OpenAI 兼容 AI Provider：Base URL、API Key、Model、连接测试、密钥掩码。
- 自动翻译独立开关；开启时自动翻译新入库的非目标语言消息，关闭时不创建后台任务。
- 每条消息单次“翻译”操作，原文始终保留，译文显示在原消息下方。
- 手动添加联系人、CRM Sandbox 导入、可选同步建档、新入站自动建档和精确进入账号级会话。
- CRM Sandbox 手工/自动建档，按 E.164 手机号去重。
- 按线索类型、地区配置首选和备用账号；支持新增、编辑、删除和命中测试。首次建会话时首选账号离线可选择在线备用账号，已有会话不静默换号。
- 二维码弹窗只在账号真正进入 `connected` 后自动关闭；连接中、重连和失败状态保留反馈与重试入口。
- 本机 PGlite 嵌入式 PostgreSQL；生产通过 `DATABASE_CLIENT=postgres` 切换标准 PostgreSQL。
- 桌面四栏工作台与移动端会话列表/聊天切换。

## 需要真实渠道继续验收

Baileys 仍需使用隔离测试号完成：

1. 真实通讯录、历史数据、入站消息、状态回执和出站文本的实际范围。
2. 两个真实账号同时在线、互不串号。

Meta 仍需使用真实测试 App、WABA、号码和公网 HTTPS 回调完成：

1. Graph 凭据与号码归属验证。
2. Webhook 订阅、签名、入站文本和状态回执。
3. 24 小时窗口内自由文本与窗口外已审核模板。

## 尚未进入本里程碑

- Meta 官方通道代码和本机 Mock Graph 契约已完成；真实 App、WABA、号码、Webhook 公网回调和模板仍待真实凭据验收。
- 图片、文件、语音上传发送、配对码登录和官方 Business App Coexistence 尚未实现。
- 生产前仍需鉴权/RBAC、Socket 租户与账号隔离、持久 Inbox/Outbox、持久任务队列、多实例账号租约和真实 CRM Adapter。
- 当前为单租户本机测试控制台，尚未实现真实 CRM Adapter 和用户登录鉴权。
- 用户尚未提供正式 OpenAI 兼容模型参数；当前活动库保留已配置的真实 OpenAI 兼容 Provider，不再使用 Mock Provider。新环境默认无 Provider、自动翻译关闭。

## 运行命令

```bash
npm install
npm run dev
```

- 控制台：http://127.0.0.1:5173
- API 健康检查：http://127.0.0.1:3100/api/health

如果 WhatsApp 二维码无法生成，先执行：

```bash
curl -I --max-time 20 https://web.whatsapp.com
```

连接超时表示需要开启可访问 WhatsApp Web 与 WebSocket 的网络/TUN 通道。
