# GoodJob CRM Agent 知识层开发文档

版本：1.0

## 1. 目标

在不依赖特定模型、不开放本地电脑控制、不改变现有 CRM 权限边界的前提下，
为内置 Agent 建立可读取、可检索、可审核、可版本化的系统知识层。模型只接收
后端编译后的上下文包，不直接读取文件系统、数据库凭据或用户账号信息。

## 2. 知识分层

| 层级 | 来源 | 权限 | 生命周期 |
| --- | --- | --- | --- |
| 系统知识 | 版本库 agent-knowledge JSON | 全员按角色读取，只读 | 随版本发布 |
| 团队知识 | 学习中心人工创建 | 团队可见，主管发布 | 草稿、待审核、已发布、归档 |
| 蒸馏打法 | 已发布业务员蒸馏结果 | 当前团队可见 | 随蒸馏版本更新 |
| 个人记忆 | 现有 Agent Memory | 个人或受控团队范围 | 待确认、启用、停用 |
| 执行经验 | Agent 或用户提交的候选知识 | 默认待审核 | 审核后进入团队知识 |

系统知识包含模块事实、字段语义、标准流程、权限政策、完成标准和常见失败。
团队知识不能修改接口风险等级、账号权限和系统政策。

## 3. 核心数据模型

AgentKnowledgeDocument 保存团队知识，字段包括：

- kind：system、module、workflow、policy、field、playbook、failure_case
- scope：system、team、company
- module：customers、leads、prospecting、communication 等业务模块
- roles：允许检索该知识的角色
- content、keywords、toolRefs、successCriteria、failureCases
- sourceType、sourceId、status、trustLevel、version、revision、checksum
- 发布人、发布时间、使用次数和最后使用时间

系统 JSON 在启动时读取并校验，不复制到业务数据库。团队知识持久化到 MySQL。

## 4. 检索与上下文编译

第一阶段采用结构化过滤和词法混合检索：

1. 先按角色、团队、状态过滤。
2. 按当前页面模块、标题、关键词、正文、工具引用和中文二元词评分。
3. 系统政策和审核知识优先于普通候选内容。
4. 同一来源只保留当前有效版本。
5. 最多返回 8 个知识单元，并记录知识 ID 和版本。

当前知识规模不新增向量数据库。检索接口保留 embedding 扩展位；未来可在不改变
Agent 上下文协议的情况下切换到 pgvector 或 Qdrant。没有 Embedding 时所有功能
仍可正常工作。

上下文包固定包含：

- 用户目标与当前 CRM 页面上下文
- 真实业务对象 ID
- 按权限检索到的知识单元和来源版本
- 当前工具目录及风险
- 业务记忆和已发布蒸馏打法
- 对话历史、执行观察和完成标准

## 5. 学习中心

Agent 页面提供知识入口，覆盖：

- 系统知识与团队知识列表
- 模块、状态和文本检索
- 新建候选知识、编辑、提交审核、发布、归档
- 检索测试，直接查看某条指令会命中哪些知识
- 索引状态、知识版本、待审核数量和检索模式

普通业务员可以提交候选知识，但不能发布团队或公司知识。主管、管理员和
超级管理员可以审核发布。系统知识不可编辑或删除。

## 6. Agent 接入

规划器和 Mission Evaluator 都必须读取同一知识上下文。知识内容只能解释系统，
不能扩大权限、修改工具风险或覆盖用户的“不发送”“只读”等约束。模型输出仍由
现有 Schema、工具白名单、签名和审批机制校验。

规划优先级固定为：已启用模型规划、服务端安全复核、执行器调用真实工具、
模型按真实结果继续评估。确定性业务规则只在未配置模型、模型调用失败或模型没有
返回有效计划时兜底，不能因为命中“新增客户”等常用意图而绕过已经启用的模型。
模型缺少不可推断的必填信息时通过 askUser 继续同一对话，禁止编造字段。

通用业务写入采用 Catalog-first 闭环：模型提出业务动作后，系统先读取运行中服务的
真实接口契约；下一轮模型按 requestSchema 生成参数；执行器调用接口；Evaluator
依据响应对象和 ID 判断完成。接口目录本身不算完成证据。用户已经明确要求新增时，
该指令可授权客户、线索、商机、待办和备忘录的单次低风险站内创建；删除、批量修改
和任何外部发送仍需单独确认。模型声称完成但没有成功写入对象 ID 时，服务端拒绝结束。

## 7. 测试与验收

- 系统知识文件可加载、校验并生成稳定 checksum。
- 客户公池、搜客、开发信、Communication 等指令能检索到正确知识。
- 未发布团队知识不会进入 Agent 上下文。
- 普通业务员无法发布；跨团队知识不可见。
- 规划和结果核验提示词均包含知识版本和引用 ID。
- 无模型配置时，搜客和其他 CRM 功能继续独立工作。
- 后端、前端和 Communication 现有测试全部通过。
- 学习中心在 13、16、24 和 27 英寸常见 PC 宽度下无重叠。

## 8. 页面能力路由

页面跳转使用统一能力目录，而不是菜单名称的完全匹配。每个页面登记真实 view ID、
页面用途、业务动作和常用表达。规则执行器按短语、中文二元词和用途相关度评分，
模型规划器读取同一页面能力目录；高可信匹配直接跳转，未知页面不得静默回到工作台。
例如“我要写单据”“做 PI”“准备商业发票和装箱单”都应进入 documents，
“写客户开发邮件”进入 development-email，“查看成交进度”进入 pipeline。
