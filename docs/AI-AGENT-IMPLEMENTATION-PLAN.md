# GoodJob CRM AI Agent 分阶段开发文档

## 1. 目标

在不替换现有 Mission Engine、不影响独立自动获客、不开放任意网页操作的前提下，把 Agent 升级为可中断、可恢复、有业务记忆、可被 CRM 事件唤醒并且可评测的站内执行助手。

开发顺序固定为：

`追加式对话与改令 -> Mission 检查点 -> 外贸业务记忆 -> CRM 事件触发 -> 评测与模型路由`

## 2. 不变的安全边界

- 搜客页面与搜客 Worker 不依赖 Agent，未配置模型时仍可独立运行。
- 读取和受控页面切换可以自动执行；CRM 写入、外部请求和外部发送按风险策略审批。
- Email、Communication 和自动触达批准的是不可变内容快照，批准后不得再由模型改写。
- 明确的“只读、不修改、不创建、不发送”约束同时在计划器和执行器生效。
- Communication 账号、翻译配置和会话仍严格按个人账号隔离。
- 恢复检查点不得重放已经完成或结果不确定的外部发送。

## 3. 阶段一：追加式对话与运行中改令

### 3.1 数据与状态

- Agent 回复以 `assistant` 事件持久化，用户补充以带时间的计划事件持久化。
- 新消息优先进入当前会话中尚未结束的 Mission；已结束 Mission 才创建新 Mission。
- 新指令到达时，未开始的旧步骤标记为 `skipped`，旧审批立即失效。
- 正在执行的请求不能伪装成已撤回；系统记录“指令到达时动作已开始”，完成后再重规划。

### 3.2 接口

- `POST /api/agent/missions/:id/steer`：向运行中 Mission 追加约束并重规划。
- `POST /api/agent/plan`：自动判断是新建 Mission、回答等待补充，还是改令当前 Mission。
- 返回完整时间线、当前动作、改令结果和失效步骤数量。

### 3.3 前端

- 用户消息和 Agent 回复只向下追加，不覆盖历史内容。
- 未完成回复显示“进行中”、当前动作、轮次和进度。
- 等待审批显示“等待确认”；等待补充显示“等你回复”；结束后固定最终回复。
- 用户停留在底部时自动跟随新消息；用户向上阅读时不强制拉回底部。

### 3.4 验收

- 连续三轮消息顺序和刷新后顺序一致。
- 运行中输入“只看德国，不要修改和发送”，后续计划只含只读工具。
- 被改令替代的旧写入/发送审批不能继续批准。
- 对话、改令和审计不能跨账号读取。

## 4. 阶段二：Mission 检查点与恢复

### 4.1 数据表

新增 `agent_mission_checkpoints`：保存 Mission、轮次、步骤快照、事件位置、状态哈希、创建原因和时间。相同状态哈希不重复保存，每个 Mission 最多保留 80 个检查点。

### 4.2 恢复规则

- 工具执行前、工具完成后、进入审批、收到改令、暂停和终态时创建检查点。
- 支持读取检查点、查看差异和从安全检查点恢复。
- 恢复后所有写入与外部步骤重新进入审批。
- Mission 已存在完成或结果不确定的外部动作时禁止回退执行，只允许查看快照。

### 4.3 验收

- 服务重启后从最后安全位置继续。
- 同一工具结果不会因恢复重复写入。
- 外部发送完成后尝试恢复会被明确阻止。
- 恢复操作有账号隔离、审计事件和自动化测试。

## 5. 阶段三：外贸业务记忆

### 5.1 记忆类型

- `user_preference`：语言、语气、市场、产品和跟进节奏。
- `company_knowledge`：公司介绍、产品优势、认证、交期和禁用表述。
- `customer_memory`：客户关注点、异议、承诺、关键人和沟通偏好。
- `team_playbook`：已发布的蒸馏打法与适用阶段。

### 5.2 规则

- 先用 MySQL/MariaDB 结构化字段和全文检索，不新增向量数据库依赖。
- CRM 事实可以直接检索；模型提炼内容先进入 `proposed`，确认后才成为 `active`。
- 每条记忆保存来源、可见范围、有效期、创建人和最后使用时间。
- 规划和核验只注入当前账号有权访问且与目标相关的少量记忆。

### 5.3 验收

- 个人记忆不能跨账号；团队记忆必须发布后共享。
- 用户可以确认、编辑、停用、删除和设置有效期。
- Agent 回复可以列出使用的记忆来源，不把推断伪装成 CRM 事实。

## 6. 阶段四：CRM 事件触发

### 6.1 首批事件

- 新线索超时未处理、客户新回复、商机长期未推进、报价/下一动作到期、高等级客户健康下降、Communication 未读、搜客任务完成。

### 6.2 自动化等级

- `notify`：只提醒。
- `internal`：允许只读分析和创建受控站内待办。
- `approval`：生成写入或外部动作，等待本人审批。

外部发送不提供无人审批等级。

### 6.3 验收

- 同一业务事实通过幂等键只触发一次。
- 触发器支持暂停、恢复、禁用和查看最近触发结果。
- 事件生成的 Mission 与手工对话 Mission 使用同一权限和审计链路。

## 7. 阶段五：评测、成本和模型路由

### 7.1 指标

- Mission 完成率、平均轮次、耗时、人工接管率和审批率。
- 工具成功率、失败类型、重试、恢复和幂等命中。
- 模型调用次数、Token、费用、延迟、超时和降级次数。
- 待办完成率、开发信回复率、客户转化率和打法实际应用效果。

### 7.2 路由

- 规则模式处理确定性查询。
- 低成本模型处理分类、摘要和简单草稿。
- 高能力模型处理背调、复杂规划和结果核验。
- 每个用途支持超时、备用模型、单 Mission 预算和每日预算。

### 7.3 验收

- 每个 Mission 可查看完整调用与费用汇总。
- 主模型失败后按配置降级，不能静默改变审批边界。
- 使用固定业务测试集比较模型和提示词版本，失败版本不能发布。

## 8. 测试与交付

每阶段必须通过：模块单测、账号隔离测试、API 集成测试、服务重启恢复测试、前端自检、生产构建和 1280/1440/1920/2560 桌面端验收。测试不得发送真实 Email 或 Communication 消息。

每阶段完成后更新本文件状态、`AI-AGENT-CLOSED-LOOP.md` 和宝塔部署包。

## 10. 实际交付

- 对话使用追加式用户/助手事件，进行中回复、等待审批、等待补充和最终回复互不覆盖。
- 运行中改令复用原 Mission，未开始步骤进入 `skipped`，旧签名审批失效；显式只读指令只保留读取工具。
- 每次 Mission 状态变化保存去重检查点；已完成 CRM 写入或存在外部动作时禁止危险回退。
- 业务记忆支持个人、客户、团队和公司四种范围，建议态与启用态分离，并按来源、有效期和账号权限检索注入。
- 自动触发覆盖线索超时、客户回复、商机停滞、下一动作到期、健康下降、Communication 未读和搜客结束；事实哈希保证幂等。
- 自动触发生成同一 Mission/审批/审计链，`notify` 强制只读，站内写入仍需确认，所有外部发送仍需确认。
- Agent 模型调用按规划/核验用途路由，主模型失败最多尝试两个备用模型；记录 Token 估算、延迟、降级、失败和估算费用。
- 默认预算为每日 10 USD、单 Mission 2 USD，可通过环境变量调整；费用为估算值，不作为供应商账单。
- 固定安全评测包含只读约束、CRM 写入审批、外部发送审批、自动提醒不外发和线索上下文五项。
- 通用业务 API 网关提供 `api.catalog`、`api.read`、`api.write`、`api.external`。目录来自运行中的真实 Express/OpenAPI 路由，支持检索和分页，不维护第二份手工接口清单。
- `GET` 业务接口可以自动执行；新增、修改和删除必须确认完整 method/path/query/body；发送、外部搜索和外部副作用必须进入外部动作后台队列。
- 登录、账号、个人资料、密码、模型密钥、个人 Communication 绑定、调试文档和递归 Agent 控制面在目录层与执行层同时拒绝。
- 通用接口结果递归清除密码、Token、密钥、凭据、会话数据和账号集合；写入成功后前台自动重读业务状态。
