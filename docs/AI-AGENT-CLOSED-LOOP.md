# GoodJob CRM AI Agent 闭环说明

## 当前闭环

AI Agent 现在采用持久化 Mission 执行链路：

`目标 → 计划 → 执行 → 观察真实结果 → 核验完成标准 → 重新规划 → 继续执行`

循环只会在目标完成、等待审批、缺少关键信息、用户暂停或取消、发生不可恢复错误、达到自主轮次上限时停止。Mission 默认最多自主执行 12 轮、保留 30 天；达到上限后可由用户补充信息继续，最高扩展到 24 轮。

Mission 在 CRM 后端运行，不依赖 Agent 页面保持打开。浏览器关闭后，未完成的读取、分析和已批准队列仍由后台执行器继续处理。

用户入口采用连续对话模式。用户消息、Agent 回复、工具步骤、审批状态和执行结果显示在同一条聊天时间线中；对话按会话 ID 持久化，可以新建对话、查看最近对话并恢复历史上下文。模型规划和结果核验只读取当前账号当前会话的记录。

它不是只能回答问题的聊天框。模型只负责选择受控工具和填写结构化参数，真实权限、数据范围、接口调用、发送动作和审计都由 CRM 后端执行。

## 已接通能力

- 页面控制：切换 CRM 模块，打开客户全景、线索详情、开发信工作台和 Communication 会话。
- 连续对话：Enter 发送、Shift + Enter 换行，支持新对话、历史会话切换和多轮上下文。
- 数据读取：客户、线索、商机管道、客户全景和待办。
- 自动获客：复用正式获客项目、搜索策略、运行队列和候选管道，支持启动搜客、持续读取来源进度、候选收获、企业复核和清洗淘汰。
- 候选转化：读取候选的企业复核与人工可联系审批；经用户再次确认后，可转为线索，并可将已有线索继续转为客户。
- 数据写入：创建待办、记录客户跟进、更新客户健康度和 A/B/C/D 分级。
- 开发信：读取真实客户或线索资料，调用个人配置的模型撰写，通过个人 SMTP 后台发送。
- Communication：使用当前业务员自己的已连接账号，通过独立 Communication 服务后台发送。
- 结果回写：发送开发信或 Communication 后写入跟进时间线；开发信还会自动生成下一次跟进待办。
- 后台队列：外部动作审批后进入持久化队列，用户离开 Agent 页面后仍继续执行。
- 自动触达序列：一次审批锁定对象、渠道、最多发送次数、每一步延时以及完整主题和正文；后台按时执行，支持暂停、继续和取消。
- 回复即停：发送前检查 Communication 入站消息、CRM 回复记录、候选回复、退订、拒绝、退信、无效渠道和线索转客户状态，命中后自动停止余下步骤。
- 客户守护：经本人批准后，按固定周期巡检本人名下客户的低健康度、跟进逾期、长期未联系和商机下一动作缺失/到期，仅创建有上限的站内待办。
- 维护幂等：同一客户的同一风险事实只创建一次待办；健康度、跟进或商机事实变化后才形成新的维护任务，公池客户不会进入个人守护。
- 蒸馏打法应用：团队发布的业务员蒸馏卡片可由业务员启用为本人当前打法；Agent 规划、结果核验和客户守护都会读取该打法。
- 打法效果记录：同一账号同时只启用一个打法，系统记录应用次数、形成维护待办数和最近使用时间，支持停用和切换。
- 对话背调：Agent 复用现有 AI 背调 API，结果持久化到 Mission 并直接打开原背调整页，不建立第二套结论。
- Communication 收件箱：Agent 可读取本人已连接账号的未读会话、最后消息和关联客户；不能读取其他业务员账号，回复发送仍需审批。
- Mission 控制：显示完成百分比、当前轮次、当前动作和停止原因；支持暂停、继续和取消。
- 结果核验：启用模型时，根据真实工具结果判断目标是否完成；未完成则生成下一轮工具步骤。
- 缺失信息恢复：Mission 可进入“等待补充”，用户下一条消息会从原检查点继续，而不是新建一次性回答。
- 审计与安全：步骤签名、账号和团队数据隔离、外部动作审批、Communication 消息幂等、服务重启防重复发送。
- 追加式回复与运行中改令：每轮消息向下追加；新指令可替换未开始步骤并使旧审批失效，不覆盖历史回复。
- Mission 检查点：状态变化自动保存去重快照；安全读取可恢复，已完成写入或存在外部动作时禁止危险回退。
- 外贸业务记忆：个人偏好、公司知识、客户记忆和团队打法先建议后确认，只向规划和核验注入当前账号可见的相关记忆。
- CRM 自动触发：线索、客户、商机、Communication 和搜客事件通过事实哈希幂等地创建受控 Mission，支持暂停、恢复和立即扫描。
- 模型治理：规划和核验分用途路由，主模型失败自动降级并留痕，按账号记录 Token、延迟、估算费用和预算使用。
- 安全评测：内置五项固定场景，覆盖只读、CRM 写入审批、外部发送审批、自动提醒和页面上下文。
- 全业务 API：专用工具未覆盖时，Agent 先读取真实接口目录，再通过通用读取、写入或外部动作工具调用原 CRM 接口；接口仍执行原有 RBAC、参数校验和数据隔离。

## Mission 状态

- `planning`：正在核对上一轮结果并规划下一轮。
- `running`：后台正在领取读取、分析、草稿或已批准动作。
- `awaiting_confirmation`：高风险写入或对外发送等待用户一次确认。
- `paused`：用户暂停；当前已发出的请求可以完成，但不会领取新动作。
- `waiting_user`：完成目标仍缺少不可推断的信息，等待用户补充。
- `completed`：完成标准已经由真实结果核验满足。
- `failed`：发生不可恢复错误或达到自主轮次上限。
- `cancelled`：用户取消；未开始动作不会再执行。

## 执行等级

- 读取、分析、草稿和页面控制：可以自动执行。
- 用户明确要求的普通站内新增、修改、记录和保存草稿：原始指令即授权，直接执行并回读核验。
- 删除、批量破坏、客户释放、丢单关闭、负责人转移等高风险站内动作：必须确认。
- 发送邮件或 Communication 消息：必须确认，确认后由后台队列执行。
- 单封开发信采用两阶段审批：先生成草稿，再把最终收件人、主题和完整正文锁定到带签名的发送步骤；用户看到并批准该快照后才发送。
- Communication 单条消息也必须在审批前锁定完整正文；缺少正文的模型步骤不能进入发送器。
- 多客户开发信：每个客户形成独立发送步骤，可一次批准全部外部步骤。
- 自动触达序列：批准的是页面中可展开核对的不可变内容快照，不是允许模型以后临时生成任意消息；每条序列最多 5 次、单步最长等待 30 天。

规则模式没有模型推理能力，只会执行确定性的安全计划并汇总真实结果。要使用“观察结果、改走其他路径、连续多轮执行”，必须在个人 AI 配置中启用可用模型。

## 与自动获客的关系

自动获客是独立业务服务，AI Agent 只是可选入口。自动获客页面与 Agent 调用同一套活动、策略、运行、Worker、清洗和候选数据：

- 未配置 AI Agent 或模型时，自动获客页面仍可正常创建、暂停、恢复和取消任务。
- Agent 失败、暂停或关闭页面，不影响已经创建的搜客运行。
- 暂停或取消 Mission 只停止 Agent 继续领取和观察动作，不会隐式取消独立搜客任务；搜客运行仍在自动获客页面管理。
- Agent 启动搜客前必须确认，因为数据源可能产生外部请求或费用。
- Agent 不能代替企业复核或人工可联系审批；没有有效审批的候选不能转为线索。
- 页面与 Agent 读取同一份任务、候选和清洗结果，不建立第二套搜客数据。

## 必要配置

开发信真实发送要求：

- 业务员在个人配置中维护发件邮箱、发件人、签名、SMTP 地址、端口、账号和授权码。
- 管理员维护公司名称、主营产品和官网。
- 如需 AI 撰写，在 AI 配置中启用开发信用途的模型。

Communication 真实发送要求：

- 当前业务员已在 Communication 中绑定并连接自己的 Baileys 或 Meta 账号。
- 客户资料中保存符合 E.164 格式的 WhatsApp 号码。
- Meta 官方账号仍受 24 小时会话窗口和模板政策约束。

## 边界

“站内助手”不等于绕过权限。Agent 只能使用工具目录中已注册的动作，不能执行任意代码、任意 SQL、读取其他业务员的个人 Communication 配置，或在没有审批的情况下向外部联系人发送内容。

通用 API 网关不会扩大当前登录人的业务权限。它只接受 `/api/` 相对路径，必须命中运行中服务的真实 OpenAPI 路由，并拒绝账号、登录、个人资料、密码、模型密钥、个人 Communication 绑定、调试文档以及递归 Agent 控制面。模型声明的风险等级与服务器重新分类不一致时，服务器拒绝执行。

直接命令也受同一约束：`GET /api/...` 自动读取；`POST /api/... {JSON}`、`PATCH /api/... {JSON}`、`DELETE /api/...` 生成待确认步骤。对外发送或访问外部来源的路径会自动升级为 `api.external`，不能伪装成普通写入。

新增业务能力时，应先新增受控工具、参数校验、权限规则、幂等策略和结果回写，再允许模型选择该工具。

已接入的正式搜客工具包括：

1. `prospect.start_search`：通过原有活动与策略服务创建真实搜客运行，属于需确认的外部动作。
2. `prospect.get_search_progress`：持续观察来源、候选、企业复核和清洗进度，复用同一个观察步骤并流式记录事件。
3. `prospect.list_candidates`：读取候选资料、复核等级、人工可联系审批和转化状态。
4. `prospect.convert_to_lead`：只允许把已有有效人工审批的候选转为线索，属于需确认的 CRM 写入。
5. `prospect.convert_to_customer`：只允许把已经转为线索的候选继续转为客户，属于需确认的 CRM 写入。

已接入的受控触达工具包括：

1. `outreach.create_sequence`：创建并批准固定触达快照，属于外部动作。
2. `outreach.get_sequence_progress`：读取本人序列、当前步骤、下一次发送时间和停止原因。
3. `outreach.pause_sequence`、`outreach.resume_sequence`、`outreach.cancel_sequence`：控制本人序列，不允许跨账号操作。

已接入的客户守护工具包括：

1. `maintenance.preview`：只读预览当前规则会识别出的客户风险和可创建待办数量。
2. `maintenance.create_watch`：审批固定的巡检频率、风险阈值、客户等级和单次待办上限后，启用后台守护。
3. `maintenance.get_progress`：读取最近巡检时间、发现数、创建数、跳过数、累计待办和下次运行时间。
4. `maintenance.pause_watch`、`maintenance.resume_watch`、`maintenance.cancel_watch`：控制本人守护策略。

客户守护不会自动修改客户健康度、分级、联系方式或商机阶段，也不会自动发送邮件、Communication 消息。需要外部触达时必须进入独立的受控触达序列并再次审批。

已接入的通用业务接口工具包括：

1. `api.catalog`：按关键词、方法、偏移量和数量读取真实业务接口及请求结构。
2. `api.read`：只允许 `GET`，自动执行后把脱敏结果加入 Mission 观察。
3. `api.write`：只允许非外部副作用的 `POST`、`PUT`、`PATCH`、`DELETE`，完整请求快照经确认后执行。
4. `api.external`：处理客户发送、外部搜索、网站访问等外部副作用，确认后进入后台队列。

## 业务员蒸馏应用

- 蒸馏卡片必须由主管或管理员发布后，业务员才能应用。
- 应用新打法会自动停用本人原来的当前打法，避免多个打法同时影响 Agent。
- Agent 模型只能把打法作为业务约束与行动参考，不能借此绕过工具权限、写入审批或外部发送审批。
- 客户守护匹配到阶段动作时，会把打法动作写入站内待办，并记录一次实际应用。
- `distillation.list_playbooks`、`distillation.activate_playbook`、`distillation.pause_playbook` 可由对话 Agent 读取或控制，启用和停用属于 CRM 写入。

邮件回复只有在已经进入 CRM 回复记录或候选回复事实时才能自动识别；当前系统没有通用 IMAP 收件服务。Communication 入站消息可直接从独立通讯服务检测。客户资料字段的无人值守自动修改仍未开放，模型不能自行扩大写入或外部发送权限。

## 页面状态与验收

- 进入 AI Agent 页面时会重新读取 Mission、自动触达、客户守护和本人当前蒸馏打法，避免从其他页面切回后显示旧状态。
- 在蒸馏页面启用或停用打法后，Agent 侧栏立即同步；后台再次读取服务端状态，页面刷新后仍保持一致。
- 外部动作审批卡展示不可变对象、渠道、次数、延时、主题和完整正文；后续触达正文可以逐条展开核对。
- 已按 1280、1440、1920、2560 像素宽度完成桌面端检查，Agent 对话区、行动计划、蒸馏卡片和长正文审批卡均无页面级横向溢出或正文截断。
- 浏览器验收只生成并取消待审批任务，没有批准或发送真实 Email、Communication 消息。
- Agent 侧栏提供业务记忆、自动触发、运行与成本三个管理入口；模型提炼内容未确认前不会影响规划。
- 自动触发的只读提醒不能产生写入或外发步骤；站内任务与审批型建议继续沿用原 Mission 审批链。
- “运行与成本”展示近 24 小时调用、成功率、延迟、Token 和估算成本，并可运行固定安全评测。

## 模型治理配置

- `AGENT_MODEL_ROUTE_PLANNING`：规划模型的配置 ID 或模型名。
- `AGENT_MODEL_ROUTE_EVALUATION`：结果核验模型的配置 ID 或模型名。
- `AGENT_DAILY_BUDGET_USD`：单账号每日估算费用上限，默认 10。
- `AGENT_MISSION_BUDGET_USD`：单 Mission 估算费用上限，默认 2。
- `AGENT_INPUT_USD_PER_MILLION_TOKENS`：输入 Token 估算单价，默认 0.5 USD/百万 Token。
- `AGENT_OUTPUT_USD_PER_MILLION_TOKENS`：输出 Token 估算单价，默认 1.5 USD/百万 Token。
- `AGENT_TRIGGER_POLL_MS`：CRM 自动触发后台扫描周期，默认 60000 毫秒。

Token 由字符数近似估算，费用只用于预算保护和趋势比较。供应商返回实际 usage 后可再扩展为“实际/估算”双口径。
