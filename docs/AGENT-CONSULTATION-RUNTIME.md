# Kevin 咨询回答 Runtime 开发文档

版本：1.0  
范围：GoodJob CRM 内置 Agent 的咨询、解释、功能介绍和业务方法回答

## 问题

咨询意图虽然已经能被 `TurnDecision` 识别，但旧链路仍把它送进工具规划模型。底层模型协议要求输出可由 `JSON.parse` 解析，咨询提示却要求纯自然语言，协议互相冲突。解析失败后又落入通用兜底，最终出现重复问候或“暂时没有形成有效回答”。

## 第一轮方案辩论

### 方案 A：只增加咨询 Skill

优点是能沉淀系统介绍、回答规范和常见问题；缺点是不能解决模型输出协议冲突、空回复、占位回复和结果解析。因此单独采用不通过。

### 方案 B：只让模型自由回答

优点是表达自然；缺点是系统功能、权限和业务流程容易回答不准，也无法形成版本化进化和回归机制。因此单独采用不通过。

### 第一轮结论

采用咨询 Skill、系统知识和模型生成组合，但必须增加独立咨询 Runtime。

## 第二轮闭环审查

咨询 Runtime 必须同时满足：

1. 咨询意图不进入工具规划，不产生 Tool Step。
2. 强制加载 `consultation`、`system-overview` 和最多两个相关业务 Skill。
3. 检索当前用户可见的系统知识和已发布团队知识。
4. 模型严格输出 `{"answer":"...","confidence":0.9,"sources":[]}`。
5. 第二次模型审校对照原问题检查覆盖度；回答只覆盖局部、过短或属于通用话术时，由审校模型重写完整答案。
6. Runtime 拒绝空回答、占位回答、执行承诺和工具计划，但不替代模型决定回答内容。
7. 模型不可用时优先使用模块固定说明，其次使用最高分知识摘要，最后明确说明缺少哪类知识；禁止回退到问候。
8. 咨询 Skill 和知识可以版本化进化，但不能扩大权限或产生写入授权。

第二轮结论：架构闭环，可进入开发。

## 测试门禁

- “商机能干什么”返回商机能力说明，工具数为 0。
- 任意系统咨询不得返回问候兜底。
- 模型按 JSON 回答契约返回时能够正确解析。
- 模型返回占位文案时使用 Skill/Knowledge 降级。
- 模型不可用时仍能根据系统知识回答已覆盖模块。
- 咨询真实写入次数为 0，历史 Mission 改动次数为 0。
