# GoodJob Agent Skills 开发规范

## 目标

Skill 是 Agent 的业务执行手册，不是接口实现，也不是权限系统。它把用户目标转换为可持续执行的业务流程，并明确完成标准、失败恢复和允许引用的 Tool。

开发初期采用少量宽 Skill，避免一个按钮或一个接口对应一个 Skill。当前只维护系统介绍、客户闭环、自动获客、客户触达四个 Skill。

## Tool 与 Skill

- Tool：确定性操作，具备输入契约、权限校验、风险等级和完成证据。
- Skill：业务目标、步骤策略、停止条件、异常恢复及可用 Tool 集合。
- Knowledge：公司资料、产品事实、团队打法和用户偏好，不承担执行控制。
- Benchmark：用真实用户表达验证 Skill 选择、Tool 轨迹和最终业务结果。

Skill 不能创建新权限。后端接口权限、个人数据隔离、外部发送确认和高风险操作确认始终由 Tool 运行时执行。

## 目录契约

每个 Skill 放在 `agent-skills/<skill-id>/`：

- `skill.json` 保存标识、版本、状态、匹配词、模块和 Tool 引用。
- `SKILL.md` 保存系统可读的业务流程、完成标准、安全边界和失败恢复。

`system-overview` 是系统 Skill，每次规划与任务复盘都会加载。其他业务 Skill 按用户目标和当前页面匹配，默认最多再加载两个。

## 编写要求

1. 先描述最终业务结果，再描述步骤。
2. 区分“接口调用成功”和“业务目标完成”，必须列出完成证据。
3. 普通站内新增和修改应直接执行；外部发送、不可逆删除、批量高影响操作保留确认。
4. 缺字段时先读接口契约，并在用户已授权“自行编写”的情况下补齐合理非敏感数据。
5. 失败后优先读取真实错误、恢复上下文并继续，不以一次 Tool 返回作为任务终点。
6. 不在 Skill 中写密钥、账号密码、客户隐私或特定用户配置。

## 拆分条件

满足以下任一条件并有 benchmark 证据后，才从宽 Skill 拆分：

- 同一 Skill 的提示长度持续影响模型规划质量。
- 两类流程使用的 Tool、完成证据和失败恢复明显不同。
- 某类任务在独立 benchmark 中连续低于目标成功率。
- 流程已有明确维护负责人和独立版本节奏。

页面菜单、单个接口或少量近义表达不是拆分理由。优先增加 trigger、补充完成标准或改进 Tool 契约。

## 开发与验收

1. 在 `agent-skills/` 新增或修改文件并更新版本号。
2. 在 `backend/src/agent-skills-test.ts` 增加匹配和 Tool 引用断言。
3. 在 Agent benchmark 中加入至少一个自然表达、一个缺字段表达和一个失败恢复场景。
4. 运行 `npm run test:agent-skills --workspace backend`。
5. 运行 Agent、benchmark、前端构建与页面自测。
6. 在系统配置的 `Agent Skills` 页面核对状态、目录、Tool 和完整说明。

生产部署通过 `AGENT_SKILLS_DIR` 指向发布目录中的 `agent-skills`。页面只读展示文件内容，初期不提供在线编辑，避免生产配置与源码版本漂移。
