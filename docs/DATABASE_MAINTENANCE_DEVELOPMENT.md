# 数据库维护工作台开发方案

## 1. 产品目标

为管理员提供一个独立的“数据库维护”页面，完成两条闭环：

1. 从本机选择 GoodJob CRM 的 MySQL `.sql` 或 `.sql.gz` 文件，浏览器本地解析，逐表迁移到当前数据库。
2. 在部署者明确允许时，将当前 MySQL 数据库备份为本地 `.sql.gz` 文件，并支持下载与删除。

业务员和销售主管不能访问页面或接口。迁移文件不上传、不保存在服务器；备份文件只有在配置开关开启时才允许写入服务器磁盘。

## 2. 配置契约

```dotenv
# 是否允许在服务器磁盘生成数据库备份。服务器空间较小时保持 false。
MYSQL_LOCAL_BACKUP_ENABLED=false

# 仅在允许本地备份时使用。支持相对项目目录或绝对路径。
MYSQL_LOCAL_BACKUP_DIR=./backups/database

# 自动清理超过指定天数的备份。0 表示不自动清理。
MYSQL_LOCAL_BACKUP_RETENTION_DAYS=7

# 数据迁移和备份的二次授权码，至少 16 位。未配置时维护写操作不可用。
MYSQL_DATA_IMPORT_TOKEN=replace_with_a_distinct_32_plus_character_random_key
```

`MYSQL_LOCAL_BACKUP_ENABLED=false` 时：

- 状态接口返回 `backup.enabled=false`。
- 创建、下载和删除备份的接口返回 `403`。
- 页面显示“服务器已禁止本地备份”，备份按钮不可用。
- 数据迁移仍可使用，且不会把源 SQL 文件保存到服务器。

## 3. 页面结构

页面位于系统配置下，命名为“数据库维护”，只对管理员和超级管理员显示。

页面不使用大量小卡片，只保留三层：

1. 顶部状态带：MySQL 连接、备份策略、最近任务。
2. 中部工作区：左侧操作输入，右侧任务进度和逐表结果。
3. 底部任务记录：备份和迁移共用一张任务表。

数据库维护必须是“系统配置”下的独立二级导航和独立 `.view`，旧迁移面板从账号管理页移除。

顶部状态带是一条连续白色工作面，高度 `72-80px`。MySQL 连接、备份策略、最近任务三列之间使用竖线分隔，不拆成三张卡片。

迁移和备份使用分段切换。任务执行区始终保留：

- 总进度条与当前阶段。
- 当前表、已处理表数、记录数、文件大小。
- 按表排列的进度行。
- 流式运行记录，包含时间、阶段、表名、结果和失败原因。
- 终态操作：下载备份、打开迁移结果、删除备份或重新执行。

左侧迁移/备份分段控件尺寸为 `280 x 36px`。备份关闭时仍允许切换到备份页查看策略，只禁用创建按钮。

右侧是一个完整任务执行面，内部只用分隔线组织“任务状态、总进度、逐表清单、流式日志”。逐表行高 `42-46px`，列为表名、状态、进度、总量、写入、跳过、失败；当前表使用左侧 `3px` 品牌蓝色条与浅蓝背景。

流式日志默认自动滚动，并提供暂停滚动、回到最新、复制和下载日志。轮询或连接中断显示“连接中断，正在重连”，不会直接把任务判为失败。未知总量使用不确定进度，不显示伪造百分比。

### PC 布局断点

| 有效视口 | 左侧操作区 | 右侧执行区 |
|---|---:|---|
| `1181-1365px` | `360px` | 剩余宽度，逐表与日志上下排列 |
| `1366-1679px` | `400px` | 剩余宽度，逐表与日志上下排列 |
| `>=1680px` | `clamp(420px, 30%, 520px)` | 剩余宽度，内部达到 `960px` 后左右分栏 |
| `<1181px` 或 125% 缩放 | 全宽 | 单列，操作区在上 |

中部工作区使用 `min-height: clamp(520px, calc(100vh - 270px), 760px)`，27 寸屏继续全宽，不设置居中最大宽度。

## 4. 任务状态机

```text
准备中 -> 运行中 -> 已完成
               -> 已失败
               -> 已取消
```

迁移阶段：

```text
本地读取 -> SHA256 -> SQL 解析 -> 目标结构核对
-> 逐表批次写入 -> 汇总校验 -> 完成/重启服务
```

备份阶段：

```text
检查开关 -> 检查 mysqldump/mariadb-dump -> 读取表清单
-> 导出结构 -> 逐表导出数据 -> 压缩 -> 计算 SHA256 -> 完成
```

## 5. 数据安全

- 只有管理员和超级管理员可访问。
- 所有写操作必须同时通过登录权限和维护授权码。
- SQL 文件在浏览器解析，服务器不保存原始上传文件。
- 迁移只接收结构化表名、字段名和值，禁止执行上传文件中的 SQL 语句。
- 不导入数据库账号、系统迁移表和维护任务表。
- 备份目录必须固定在配置目录内，下载和删除只通过任务 ID 定位文件，禁止路径参数。
- `mysqldump` 密码不出现在命令行参数和日志中。
- 备份失败必须删除 `.partial` 文件。
- 迁移冲突默认跳过，覆盖同 ID 必须由管理员主动选择。

## 6. 后端能力

### 状态与历史

- `GET /api/system/database-maintenance/status`
- `GET /api/system/database-maintenance/jobs`
- `GET /api/system/database-maintenance/jobs/:id`

### 迁移

兼容现有 `/api/system/database-import/*`，补充任务阶段、逐表总量、当前表、事件流和取消状态。

### 备份

- `POST /api/system/database-backups/jobs`
- `GET /api/system/database-backups/jobs/:id/download`
- `POST /api/system/database-backups/jobs/:id/cancel`
- `DELETE /api/system/database-backups/jobs/:id`

## 7. 两轮自我辩论

### 第一轮：源文件是否上传服务器

方案 A：上传完整 SQL，后端统一执行。优点是可断点续传，缺点是占用服务器磁盘、扩大 SQL 注入面，并违背低存储目标。

方案 B：浏览器解析后按结构化批次迁移。优点是不保存源文件、已有实现可复用、服务端不执行任意 SQL；缺点是页面关闭后不能继续上传中的任务。

结论：采用方案 B。数据库迁移属于管理员主动维护任务，页面关闭后可查看已完成批次，但重新开始时需要重新选择文件。安全和低存储优先。

### 第二轮：备份默认开启还是默认关闭

方案 A：默认开启，更容易发现功能，但服务器磁盘可能被快速占满。

方案 B：默认关闭，由部署者显式开启并配置目录与保留天数。功能可发现，但页面明确说明当前策略。

结论：采用方案 B。产品不能替部署者决定磁盘成本；关闭时前后端双重禁止，不能只隐藏按钮。

### 第三轮：是否每个表都做成独立卡片

方案 A：卡片容易强调状态，但几十张表会产生大量边框和视觉噪音。

方案 B：使用一张连续的表进度清单，行间分隔，当前表使用窄色条强调；右侧流式记录共用一个执行面板。

结论：采用方案 B。页面只保留大工作区，不嵌套卡片，适合 13、14、16、24、27 英寸 PC。

## 8. 验收标准

- 配置关闭时，页面明确禁用备份，接口无法绕过。
- 配置开启时，可生成 `.sql.gz`、看到逐表进度、下载并删除。
- 迁移过程中每个表可看到总量、写入、跳过和失败数量。
- 流式记录按时间追加，失败时保留真实表名和错误原因。
- 真实 MySQL 测试完成“建测试表 -> 写入示例数据 -> 备份 -> 清空 -> 迁移 -> 回读一致”。
- 管理员以外账号无法看到页面，直接访问接口返回 `403`。
- 前端至少验证 `1280x720`、`1440x900`、`1536x864`、`1920x1080`、`2560x1440`，并验证 `1280` 视口下的 `125%` 浏览器缩放。
- 所有视口无横向溢出、标题不截断、日志不挤压操作区、运行中任务首屏可见。

## 9. 高级美工审核结论

审核要求已经全部纳入本方案：独立导航与页面、连续状态带、单一执行面、连续逐表行、完整日志控制、备份禁用态、有效视口与缩放验收。

视觉规范沿用系统令牌：页面底色 `#f5f7fb`、工作面白色、边线 `#dfe5ef`、主操作 `#3157d5`、成功 `#16a36a`、警告 `#d99518`、失败 `#de5a5a`。状态同时使用图标和文字，不只依赖颜色。

结论：美术/UX 审核通过，可以进入开发。
