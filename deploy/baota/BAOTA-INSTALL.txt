GoodJob CRM 宝塔 Linux 安装说明
===============================

一、安装前准备（不需要宝塔网页操作）

1. 域名 DNS 的 A 记录已经指向服务器公网 IP。
2. 宝塔服务器已经安装并运行 Nginx、MySQL 8.0+、PostgreSQL 14+、Node.js 22+。MariaDB 10.x 不兼容 CRM 数据结构；WhatsApp 生产环境不使用 PGlite。
3. 确认服务器使用 systemd，并且可以访问 npm 软件源。
4. SSL 可以先不配置；脚本会先部署 HTTP，正式上线后建议再通过宝塔或 certbot 开启 HTTPS。

纯终端安装器会自动创建 MySQL 数据库、业务用户和 Nginx 网站配置，不需要提前在宝塔面板创建网站或数据库。
安装脚本不会开放 4188 或 3100 端口。
CRM 后端只监听 127.0.0.1:4188，WhatsApp 插件只监听 127.0.0.1:3100，均由宝塔 Nginx 反向代理。

二、上传和安装

把整个压缩包上传到服务器，例如 /root，然后执行：

  tar -xzf GoodJob-CRM-Baota-*.tar.gz
  cd GoodJob-CRM-Baota-*
  cp deploy.conf.example deploy.conf

编辑 deploy.conf，只需要重点修改：

  DOMAIN       宝塔网站绑定的正式域名，不含 http、https 和路径
  DB_NAME      要自动创建的数据库名
  DB_USER      要自动创建的业务用户名
  DB_PASSWORD  业务数据库密码
  MYSQL_ROOT_PASSWORD  MySQL root 密码；root 支持本机 socket 登录时可留空
  WHATSAPP_PLUGIN_PORT WhatsApp 插件本机端口，默认 3100，一般不要修改

默认 AUTO_CREATE_DATABASE=true、AUTO_CREATE_SITE=true，表示纯终端模式。

如网站还可以通过其他域名访问，在 EXTRA_ALLOWED_ORIGINS 中填写完整来源，
例如 https://www.crm.example.com。多个来源使用英文逗号分隔，不要带路径或末尾斜杠。

保存后执行新的可靠部署入口：

  bash deploy-goodjob.sh --check-package
  sudo bash deploy-goodjob.sh

deploy-goodjob.sh 会自动读取 deploy.conf，完成以下工作：

  - 校验 PACKAGE-MANIFEST.sha256 中的每一个安装包文件和数据库初始化文件
  - 安装 Node.js 生产依赖并使用包内已构建的 CRM 前后端与 WhatsApp 插件产物
  - 升级前停止旧 CRM 与 Communication 服务
  - 首次安装时初始化空数据库；升级时仅读取已有结构并增量补齐
  - 部署流程不自动调用 mysqldump，不在升级期间生成或恢复业务数据库副本
  - 自动生成 MySQL 数据迁移授权码，原始 SQL 文件仅在浏览器本地解析
  - 自动创建 WhatsApp 插件的独立 PostgreSQL 数据库、用户和迁移
  - 生成独立生产密钥
  - 创建并启动 CRM 与 WhatsApp 两个 systemd 服务
  - 接入宝塔 Nginx 的 API、前端和 WebSocket 代理
  - 检查 Nginx 配置是否真正加载，而不只是写入了文件
  - 检查 CRM 首页、API、Communication 独立页面、静态资源和 API
  - 拦截错误域名、错误协议、CORS_ORIGINS / WEB_ORIGIN 不一致
  - 提前识别 4188/3100 被非预期进程占用，避免 EADDRINUSE
  - 自动修复静态文件权限，避免 CRM 或 Communication 返回 403
  - 识别 Communication 打开成 CRM 主界面和 index.htmlindex.php 导致的 500
  - 生成 /www/server/goodjob-crm/shared/deployment-report.txt 验收报告

首次安装建议使用空数据库。脚本会导入：

  - 当前完整数据库结构
  - 40 个相互隔离的公测团队管理员
  - 不含客户、线索、商机、待办等业务数据

40 个管理员全部核验成功后，旧通用管理员 admin@goodjob.com 会被删除。凭据保存在
/www/server/goodjob-crm/shared/beta-admin-credentials.txt，文件权限为 600；登录界面不会自动填写账号或密码。
升级任一步失败时，安装器会恢复旧版本链接、程序配置和服务；数据库只执行向前兼容的幂等结构补齐，不自动生成或恢复数据库备份。

三、安装后的检查

  systemctl status goodjob-crm
  journalctl -u goodjob-crm -f
  curl http://127.0.0.1:4188/api/health
  curl http://127.0.0.1:3100/api/health

也可以使用随包附带的服务管理脚本：

  sudo bash manage-service.sh start
  sudo bash manage-service.sh restart
  bash manage-service.sh status
  bash manage-service.sh health
  sudo bash manage-service.sh logs
  sudo bash manage-service.sh verify

浏览器访问：

  https://你的域名/
  https://你的域名/api/docs/

WhatsApp 界面位于：

  https://你的域名/whatsapp-plugin/

Swagger 需要先使用管理员账号登录。

四、没有提前开启 HTTPS

先在宝塔网站设置中申请并开启 SSL，然后执行：

  sudo sed -i \
    's/^SESSION_COOKIE_SECURE=false$/SESSION_COOKIE_SECURE=true/' \
    /www/server/goodjob-crm/shared/.env
  sudo systemctl restart goodjob-crm

再使用 HTTPS 登录并复测。不要在公网公测期间继续使用 HTTP。

五、以后升级代码

首次成功部署后，脚本会把配置安全保存到：

  /www/server/goodjob-crm/shared/deploy.conf

新版本解压后不需要再复制或重填 deploy.conf。直接在新包目录执行：

  bash deploy-goodjob.sh --check-package
  sudo bash deploy-goodjob.sh

脚本会自动读取共享配置，并固定 REUSE_EXISTING_DATABASE=true、
REPLACE_DATABASE=false。它会先停止旧 CRM 与 Communication 服务，再保留
数据库与原有加密密钥、发布新代码、执行迁移和完整验收。

只有首次安装、域名/数据库账号变更，才需要重新提供 deploy.conf。

六、数据库升级边界

部署器只复用现有数据库并增量补齐结构，不会在安装或升级过程中自动备份、清库或恢复业务数据。
旧 deploy.conf 中的 REPLACE_DATABASE 必须保持 false；设置为 true 时部署会立即停止。

系统另有独立的“系统配置 -> 数据库维护”工作台，用于管理员主动迁移数据，以及在部署者明确允许时手动创建本地备份。默认配置禁止在服务器磁盘生成备份：

  MYSQL_LOCAL_BACKUP_ENABLED=false
  MYSQL_LOCAL_BACKUP_DIR=/www/server/goodjob-crm/shared/database-backups
  MYSQL_LOCAL_BACKUP_RETENTION_DAYS=7

磁盘空间有限的服务器应保持 false，此时页面会明确显示备份不可用，后端接口也会拒绝创建、下载和删除备份。自行部署且确需备份时，将开关改为 true，确认目录容量和权限后重启服务：

  sudo sed -i 's/^MYSQL_LOCAL_BACKUP_ENABLED=false$/MYSQL_LOCAL_BACKUP_ENABLED=true/' /www/server/goodjob-crm/shared/.env
  sudo install -d -o goodjob-crm -g goodjob-crm -m 700 /www/server/goodjob-crm/shared/database-backups
  sudo systemctl restart goodjob-crm

数据迁移使用浏览器本地选择的 .sql 或 .sql.gz 文件。源文件只在浏览器本地解析，不上传或保存在服务器；执行维护写操作仍需 MYSQL_DATA_IMPORT_TOKEN。

七、常用目录

  程序目录：/www/server/goodjob-crm
  当前版本：/www/server/goodjob-crm/current
  环境文件：/www/server/goodjob-crm/shared/.env
  可选数据库备份目录：/www/server/goodjob-crm/shared/database-backups
  配置回滚目录：/www/server/goodjob-crm/shared/rollback（不含业务数据库数据）
  systemd： /etc/systemd/system/goodjob-crm.service
  WhatsApp systemd：/etc/systemd/system/goodjob-crm-whatsapp.service
  WhatsApp 环境文件：/www/server/goodjob-crm/shared/whatsapp-plugin.env
  WhatsApp 数据目录：/www/server/goodjob-crm/shared/whatsapp-plugin/

环境文件权限为 600。不要把它下载、提交到 SVN，或发给非运维人员。
需要使用系统设置中的 MySQL 数据迁移时，由服务器管理员读取 MYSQL_DATA_IMPORT_TOKEN 并在迁移完成后妥善保管。

八、安装包内文件

  deploy.conf.example   部署配置模板，复制为 deploy.conf 后修改
  deploy-goodjob.sh     推荐的一键安装、升级、验收和诊断入口
  one-click-install.sh  兼容旧命令，会自动转到 deploy-goodjob.sh
  manage-service.sh     启动、停止、重启、日志和健康检查
  install-baota.sh      底层安装器，一般不需要手动修改
  PACKAGE-MANIFEST.sha256  包内逐文件完整性清单
  LICENSE / NOTICE      CRM 核心 Apache-2.0 许可证与声明
  THIRD_PARTY_NOTICES.md  WhatsApp/Communication 等第三方组件来源
  BAOTA-INSTALL.txt     本说明

不要修改源码中的 .env。生产环境实际配置由安装器生成在：

  /www/server/goodjob-crm/shared/.env
